About me

I'd rather find the flaw
than hope it isn't there

I'm Vaishnavi Goyal, a Computer Science undergraduate at PES University, Bengaluru, on scholarship with a CGPA of 8.42. My focus sits at the intersection of quality engineering and adversarial machine learning.

Most people build software and hope it holds. I'm more interested in the opposite question — where does this break, and who could make it break on purpose? I've run white-box attacks (FGSM, PGD) against financial AI models to surface vulnerabilities in transaction logic, then built the defensive pipeline to harden them.

That curiosity runs deep as well as wide: a mini-Docker container runtime written in C with Linux kernel modules and UNIX socket IPC, a JavaScript syntax validator built from lexical analysis and context-free grammars, a custom port scanner, and full-stack platforms — including this site, backend and auth included.

I'm early in my degree with a lot left to learn, and that's the part I enjoy. Hand me something unfamiliar and I'll go find out how it works.

How I work

What I'd bring to your team

I'm early in my career, so instead of a long list of job titles, here's how I actually operate — with the evidence attached.

01 — Rigour

I test like an adversary

Rather than checking that software works, I ask how someone could make it fail. I built an end-to-end adversarial security framework that stress-tests financial AI models (XGBoost, DistilBERT, ResNet) and logs every result into an auditable telemetry trail.

02 — Depth

I go one layer lower than I need to

Using Docker wasn't enough, so I wrote a container runtime in C with UNIX socket IPC and Linux kernel modules. Understanding the layer beneath the abstraction is usually what makes the hard bugs solvable.

03 — Learning

I get up to speed fast

Compiler design, embedded sensor fusion, kernel modules, full-stack auth — most of what I've built started from zero knowledge. Give me an unfamiliar tool and I'll be productive with it quickly.

04 — Adaptability

I'm comfortable when plans change

My projects span adversarial ML, low-level systems, data analysis, hardware, and web. Switching context doesn't slow me down — I adjust, ask the right questions, and keep things moving.

05 — Follow-through

I finish what I start

Every project here shipped as something that runs, not a half-built demo. I take feedback without ego, ask questions early instead of guessing, and close the loop without needing to be chased.
